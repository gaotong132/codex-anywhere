# 参与贡献

[English](CONTRIBUTING.md) | 简体中文

感谢你帮助改进 Codex Anywhere。请让改动始终服务于项目定位：面向单用户、自托管场景，通过手机 Web
连接运行于用户自有执行节点的 Codex。

## 开始开发

要求 Node.js 22+ 和 npm；CI 会覆盖 Node.js 22 与 24。

```bash
npm ci
npm run check
npm run build
```

源码和测试统一使用严格 TypeScript，样式使用 SCSS。不要提交生成的 `build/` 或 `dist/`。协议、鉴权、
重连、历史、审批、附件、文件访问或渲染行为发生变化时，应增加聚焦的回归测试。

## 仓库结构

| 路径 | 职责 |
| --- | --- |
| `web/src` | React 手机界面、SCSS、国际化、浏览器身份、历史、预览和内容渲染 |
| `src/server` | HTTP/WebSocket 转发、端点鉴权、路由和设备注册表 |
| `src/connector` | Codex app-server/Desktop 集成、历史、文件、审批和重连 |
| `src/shared` | 严格协议、鉴权、加密、活动状态、消息和共享文件类型基础能力 |
| `test` | 集成、行为、安全与回归测试 |
| `scripts` | 转发服务管理，以及 Windows、Linux 连接器安装和守护 |
| `docs` / `deploy` | 用户文档、示意图和可选入口示例 |

## 设计约束

1. 保持单用户、自托管架构，不加入遥测、托管会话存储、通用远程 Shell、自动 fork 或自动设备信任。
2. 不在日志或 Web 界面暴露凭据、设备身份材料、原始工具输出或不必要的本机路径。
3. 本机文件下载和高权限 Codex 操作保留明确确认；内联预览必须保持有界、受根目录限制、使用类型白名单
   且只读；Desktop 已持有的审批不能展示为 Web 可操作。
4. 协议、文件系统、重连、rollout/历史映射、乐观消息和实时动画都属于安全或正确性敏感区域，必须为
   具体故障增加回归测试。
5. 长会话处理保持有界和增量，避免读取完整历史、使用不稳定 React key，或从不断变化的传输快照推导
   动画状态。
6. 把执行环境视为隔离边界。请求、安全通道、会话选择、未读状态、记忆路径、下载和附件恢复都不能
   静默切换到另一个连接器路由；切换环境时，已经被旧节点接受的任务可以继续运行。
7. 行为、部署、信任边界或命令变化时，同步更新英文和简体中文文档。

网络协议只有一个精确的当前版本。禁止增加明文、旧版本或缺失能力的兼容路径。强制线格式或能力集合
变化必须同步修改浏览器、转发服务和连接器，提升协议版本，并在测试中拒绝旧节点。即使新增协调动作
不改变强制能力集合，也必须增加浏览器/连接器路由测试，并按同一提交部署两端。

Pull Request 应足够聚焦，便于审阅和说明用户价值。只有成熟依赖能够明显减少维护负担、仍在积极维护，
且不会削弱浏览器、转发服务或本机信任边界时，才应引入。大型渲染器应按需加载，输入必须有界，生成
标记必须清洗，并始终保留安全纯文本回退。

## 补充检查

- 修改 POSIX 服务脚本后，在 POSIX shell 对每个改动脚本执行 `sh -n`。
- 辅助命令与中英文部署指南保持一致。
- 多环境改动至少验证两个同时在线的连接器路由，以及 `desktop`、`headless` 两种投递模式。
- 使用长标题、长文件名、长进度文字和三行活动状态检查手机布局。文件预览变化还必须覆盖长代码行、
  语法着色回退、“下载/关闭”控件，以及二进制或不支持文件的处理路径。
- 修改手机界面后，运行 `npm run docs:hero`，通过文档专用 React 示例重新生成 README 首图；如果未能
  自动找到 Edge 或 Chrome，可设置 `CODEX_ANYWHERE_BROWSER`。
- 创建版本 Tag 前确认包版本，更新全部用户文档，完成检查和构建，并标记已经验证的准确提交。

## 安全与测试数据

安全问题请使用 GitHub 私密漏洞报告。公开 Issue、截图、测试数据和示例不得包含凭据、真实私有主机、
个人项目名、会话内容或真实本机路径；请使用保留示例域名和文档专用 IP 网段。
