# 参与贡献

[English](CONTRIBUTING.md) | 简体中文

感谢你帮助改进 Codex Anywhere。请让改动始终服务于项目核心定位：面向单用户、自托管场景，在手机上
连接运行于用户自己电脑的 Codex。

## 开发流程

要求 Node.js 22+ 和 npm。

```bash
npm ci
npm run check
npm run build
```

源码和测试统一使用严格 TypeScript，不要提交生成的 `build/` 或 `dist/`。协议、鉴权、重连、文件访问、
历史映射等行为发生变化时，应增加针对性测试。在合理范围内保持转发服务与连接器协议向后兼容；如果
无法兼容，必须明确说明两端需要同时升级。

## 仓库结构

| 路径 | 职责 |
| --- | --- |
| `web/src` | React 手机 Web 界面、内容渲染、国际化和浏览器设备身份 |
| `src/server` | HTTP/WebSocket 转发、鉴权、路由和设备注册表 |
| `src/connector` | 本机 Codex/Desktop 集成、附件、下载和重连逻辑 |
| `src/shared` | 转发服务与连接器共用的消息帧和鉴权基础能力 |
| `test` | Node 集成测试与行为回归测试 |
| `scripts` | Windows 安装、DPAPI 凭据处理和连接器守护进程 |
| `docs` / `deploy` | 运维文档和参考入口配置 |

## 项目约束

1. 默认架构保持单用户、自托管。
2. 不加入遥测、托管会话存储、自动设备信任，也不向日志或 Web 界面暴露密钥和设备身份材料。
3. 文件下载和高权限 Codex 操作必须保留明确确认。
4. 转发协议、本机文件路径、XML/历史内容展示和重连行为都属于安全或兼容性敏感区域，需要回归测试。
5. 用户可见行为变化时，同步更新英文和简体中文文档。

Pull Request 应足够聚焦，便于审阅和说明用户价值，避免无关格式化或依赖升级。只有成熟依赖能够明显
减少维护负担、且不会削弱浏览器或本机信任边界时，才应引入。

## 安全与测试数据

安全问题请使用 GitHub 私密漏洞报告。公开 Issue 和测试数据不得包含凭据、私有主机名、IP 地址、
会话内容、真实项目名或真实本机路径；请使用保留示例域名和文档专用 IP 网段。
