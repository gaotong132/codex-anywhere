# 安全策略

[English](SECURITY.md) | 简体中文

## 支持版本

只支持 `main` 分支的最新提交。Codex Anywhere 面向单个可信用户，不是多租户服务。

## 报告漏洞

请使用 [GitHub 私密漏洞报告](https://github.com/gaotong132/codex-anywhere/security/advisories/new)。
不要在公开 Issue 中包含凭据、Token、私有主机名、IP 地址、会话内容或本地文件系统路径。

## 部署检查清单

- 浏览器客户端和连接器必须使用相互独立的 Token，每个 Token 至少由 32 字节密码学安全随机数据生成。
- 两个 Token 都保存在仅 root 可读的转发服务 `.env`。Windows 安装器使用当前用户 DPAPI 保存连接器
  Token 和连接器设备密钥；如果安装时提供浏览器 Token，则会将其另存为独立的 DPAPI 记录，仅用于
  管理员复制到可信浏览器，连接器进程不会获得浏览器 Token。浏览器 Token 仍建议保存在密码管理器中。
- 设备注册表卷必须持久化并仅由 root 管理。通过加密的管理员会话，根据角色、标签、来源地址和请求
  时间识别刚刚发起的请求；请求无法明确确认时绝不能批准。定期检查待批准请求，并撤销丢失或停用的设备。
- 远程连接优先使用 `wss://`。项目允许运维人员选择明文 `ws://`，但它会暴露转发内容，并允许主动
  网络攻击者干扰已认证连接。质询—响应认证可以避免直接发送 Token，但不能代替传输加密。
- 公网 WSS 应在持续维护的入口终止 TLS，并让转发服务只监听回环地址。Compose 示例只发布
  `127.0.0.1:3300`。如果选择直接 WS，应使用防火墙限制来源，并将其视为明文传输。
- 设置 `BRIDGE_TRUST_PROXY=1` 时，必须保证转发服务只能通过代理访问，并由代理覆盖 `X-Real-IP`。
- 在可行范围内用防火墙限制 SSH 和 HTTPS；SSH 使用密钥认证，并及时更新 ECS。
- 关闭反向代理访问日志或设置很短的保留期。客户端 IP、主机名、路径和错误诊断均属于私密元数据。
- 缩小 `CODEX_ALLOWED_ROOTS`，保持 `CODEX_ALLOW_ANY_FILE_DOWNLOAD=0`，除非确有需要，否则不要
  为连接器开启网络访问。
- 凭据一旦出现在聊天、终端输出、日志、截图、提交或 CI 产物中，应立即轮换。
- 仓库改为公开前，应审计所有可达 Git 历史，而不仅是当前工作区。

## 信任模型与数据处理

ECS 使连接器电脑无需接收入站公网流量。浏览器和本地连接器都主动建立出站连接；公网环境推荐 WSS。
项目文件和 Codex 执行始终留在本地。转发服务没有会话数据库，也不会有意持久化消息、附件预览或
下载分块。

但 ECS 转发服务仍属于信任边界。TLS 在 ECS 反向代理终止，因此代理和转发进程能在内存中看到
明文帧。本项目没有提供对 ECS 运维方或云厂商隐藏内容的应用层端到端加密。应保护进程内存、`.env`、
代理错误日志、备份、DNS、云账号以及所有具有主机管理权限的人员。

浏览器 Token 是浏览器的第一认证因素。活动标签页将它保存在 `sessionStorage`（不是持久化本地存储），
ECS 则将它保存在仅 root 可读的 `.env`。连接器 Token 可注册或替换本地连接器；它保存在 ECS 的
`.env`，Windows 安装器还会将其保存在当前用户 DPAPI 存储中。两个角色必须分离，避免浏览器 Token
泄露后被用于冒充连接器。

WebSocket 认证还要求已批准设备身份提供 Ed25519 签名。签名将设备公钥与新的 256 位质询、HMAC
证明、角色和连接器路由 ID 绑定；原始 Token 和设备私钥不会发送到转发服务。浏览器设备密钥保存在
对应浏览器配置中，Windows 连接器密钥由当前用户 DPAPI 保护。注册表只存储公钥和配对元数据。
捕获的证明无法重放，单独的 Token 只能创建可见的待批准请求，不能建立已认证会话。认证连接默认
一小时过期，重连时生成新证明；重复认证失败会按客户端地址临时锁定。

文件下载必须由浏览器明确确认，并使用随机、短时、仅限单文件且绑定客户端的能力凭证。连接器会规范化
路径、拒绝目录和路径逃逸、持有稳定文件句柄、检测传输期间的修改、限制分块速率，并且只记录散列后的
本地审计标识。启用不受限下载会有意扩大这一安全边界。

设备管理只能在转发服务主机上操作。默认命令列出待批准请求并在批准前确认；以下命令可以列出或撤销
已批准设备，而且不会输出设备 ID、请求 ID 或公钥：

```bash
docker compose exec bridge node build/server/device-admin.js list-approved
docker compose exec bridge node build/server/device-admin.js revoke
```

正在运行的转发服务会在下一次心跳时发现撤销并关闭该设备的活动连接，通常不超过 30 秒，无需重启。

## Token 可能泄露时

1. 直接视为已泄露，不要等待滥用证据。
2. 运行上面的管理员 `revoke` 命令，撤销受影响的浏览器或连接器身份。如果设备私钥也可能泄露，即使 Token 仍安全，
   也应视该身份为已失陷。Web 客户端无法读取注册身份和配对元数据。
3. 只有 `BRIDGE_CLIENT_TOKEN` 泄露时，生成新随机值替换并重启转发服务。重启会关闭现有浏览器连接，
   连接器凭据仍然有效。
4. `BRIDGE_CONNECTOR_TOKEN` 泄露时，在转发服务端替换它，使用新 Token 重新运行连接器安装器，然后
   同时重启转发服务和连接器。
5. 检查 ECS/代理日志、浏览器扩展、剪贴板历史、Shell 历史、截图、CI 输出、密码管理器访问记录和
   异常连接器替换；同时轮换一并暴露的基础设施凭据。

## 不在防护范围内

Codex Anywhere 不是多租户身份提供方、零信任网关或通用远程 Shell。它不能防御已失陷的连接器电脑、
已失陷的 ECS root 账号、能够使用已批准浏览器身份的恶意扩展、所有必需凭据同时泄露，或用户主动批准
的恶意 Codex 操作。
