# 安全策略

[English](SECURITY.md) | 简体中文

## 支持版本

只支持 `main` 分支的最新提交。Codex Anywhere 面向单个可信用户，不是多租户服务。

## 报告漏洞

请使用 [GitHub 私密漏洞报告](https://github.com/gaotong132/codex-anywhere/security/advisories/new)。
不要在公开 Issue 中包含凭据、Token、私有主机名、IP 地址、会话内容或本地文件系统路径。

## 部署检查清单

- 浏览器客户端和连接器必须使用相互独立的 Token，每个 Token 至少由 32 字节密码学安全随机数据生成。
  浏览器注册优先使用一次性链接，把浏览器 Token 只保留为管理员恢复凭据，不要分发给每个浏览器。
- 两个 Token 都保存在仅 root 可读的转发服务 `.env`。Windows 安装器使用当前用户 DPAPI 保存连接器
  Token 和连接器设备密钥；如果安装时提供浏览器 Token，则会将其另存为独立的 DPAPI 记录，仅用于
  管理员复制到可信浏览器，连接器进程不会获得浏览器 Token。浏览器 Token 仍建议保存在密码管理器中。
- 设备注册表卷必须持久化并仅由 root 管理。只在加密的管理员会话中创建一次性浏览器配对。尚未使用的
  十分钟链接属于临时密钥，不要粘贴到日志、Issue 或聊天中。定期检查恢复流程的待批准请求，并撤销
  丢失或停用的设备。
- 通知权限是可选项。Web Push 订阅和转发服务生成的 VAPID 私钥只保存在受保护状态卷中；不要公开该卷，
  也不要在未加密的情况下备份。
- 远程连接优先使用 `wss://`。项目允许运维人员选择直接 `ws://`，应用帧仍会端到端加密，但普通
  HTTP/WS 会向网络攻击者暴露 Web 代码分发、配对引导、元数据和可用性。应用层加密不能替代传输加密。
- 公网 WSS 应在持续维护的入口终止 TLS，并让转发服务只监听回环地址。Compose 示例只发布
  `127.0.0.1:3300`。如果选择直接 WS，应使用防火墙限制来源，并将 Web 分发和元数据视为未受保护。
- 设置 `BRIDGE_TRUST_PROXY=1` 时，必须保证转发服务只能通过代理访问，并由代理覆盖 `X-Real-IP`。
- 在可行范围内用防火墙限制 SSH 和 HTTPS；SSH 使用密钥认证，并及时更新 ECS。
- 关闭反向代理访问日志或设置很短的保留期。客户端 IP、主机名、路径和错误诊断均属于私密元数据。
- 缩小 `CODEX_ALLOWED_ROOTS`，保持 `CODEX_ALLOW_ANY_FILE_DOWNLOAD=0`，除非确有需要，否则不要
  为连接器开启网络访问。
- 凭据一旦出现在聊天、终端输出、日志、截图、提交或 CI 产物中，应立即轮换。
- 仓库改为公开前，应审计所有可达 Git 历史，而不仅是当前工作区。

## 信任模型与数据处理

ECS 使连接器电脑无需接收入站公网流量。浏览器和本地连接器都主动建立出站连接；公网环境推荐 WSS。
项目文件和 Codex 执行始终留在本地。转发服务没有会话数据库，也不会有意持久化消息、附件预览或
下载分块。

用户主动开启通知后，转发服务会持久化该已批准浏览器的推送服务端点和加密材料。浏览器断开时，连接器
只发送通用事件类别 `completed` 或 `approval`，转发服务再通过 Web Push 转发。这会向转发服务和推送
提供商暴露事件类别与发生时间，但不会提供任务 ID、会话标题、消息、项目名、路径、附件或工具输出。
浏览器仍在线时使用本地通知。最终投递还受浏览器和手机系统后台策略影响，不能保证必达。

协议 v3 会拒绝过期或能力不完整的节点，并强制在 WebSocket 认证后建立应用层加密通道：浏览器和
连接器用已批准的 Ed25519 身份验证临时
X25519 密钥，通过 HKDF-SHA-256 派生双向密钥，再用 XChaCha20-Poly1305 保护有序 JSON 帧。消息、
图片预览、可视化 HTML 和下载分块都会以密文穿过转发服务。转发服务仍能看到公开设备身份、路由 ID、
连接时间、帧方向和近似大小。

ECS 仍是信任边界，而不是零信任组件。它负责提供浏览器代码、保存角色 Token 与设备信任注册表，并
强制执行当前协议。宿主机或 root 管理员被攻破后，可能修改后续浏览器代码、替换信任记录、注册攻击者
控制的设备或拒绝服务。因此当前端到端加密主要防止正常转发进程读取内容和意外日志泄露，并不能防御同时控制注册
与代码分发的恶意宿主机。应保护 `.env`、注册表、代理日志、备份、DNS、云账号和所有主机管理员。
系统不存在旧协议或明文应用帧回退路径；浏览器、转发服务和连接器版本不一致时会关闭连接，必须同步升级。

浏览器优先使用随机、十分钟有效且仅可使用一次的配对链接完成引导。密钥位于 URL 片段中，WebSocket
建立前就会从地址栏移除；注册成功前只保存在 `sessionStorage`。转发服务只持久化 SHA-256 校验值和
有效期，并在成功使用后删除记录。浏览器 Token 仍是恢复引导凭据，保存在仅 root 可读的 ECS
`.env`；使用时只会在批准前短暂存在浏览器 `sessionStorage`。连接器 Token 可注册或替换本地连接器；它保存在 ECS 的
`.env`，Windows 安装器还会将其保存在当前用户 DPAPI 存储中。两个角色必须分离，避免浏览器 Token
泄露后被用于冒充连接器。

WebSocket 认证要求已批准设备身份提供 Ed25519 签名。注册过程会把一次性 HMAC 证明、设备公钥和
新的 256 位质询绑定；后续浏览器重连只需要用已批准设备密钥签署新质询。连接器和恢复 Token 流程
仍会把签名绑定到质询、HMAC 证明、角色和连接器路由 ID。原始 Token、配对密钥和设备私钥都不会发送到转发服务。浏览器设备密钥保存在
对应浏览器配置中，Windows 连接器密钥由当前用户 DPAPI 保护。注册表只存储公钥和配对元数据。
捕获的证明无法重放，单独的 Token 只能创建可见的待批准请求，不能建立已认证会话。认证连接默认
一小时过期，重连时生成新证明；重复认证失败会按客户端地址临时锁定。

助手 Markdown 可以嵌入 `CODEX_ALLOWED_ROOTS` 中的本机 JPEG、PNG 或 WebP。连接器会校验规范化路径和
实际文件类型，只返回受大小限制的 WebP 预览；SVG 和其他主动或不支持的格式仍只能下载。原文件下载
必须由浏览器明确确认，并使用随机、短时、仅限单文件且绑定客户端的能力凭证。连接器会拒绝目录和路径
逃逸、持有稳定文件句柄、检测传输期间的修改、限制分块速率，并且只记录散列后的本地审计标识。启用
不受限下载只会扩大下载边界，不会扩大自动图片预览根目录。

Codex 生成的 `.html` 只允许从规范化后的 `.codex/visualizations` 目录预览，大小上限为 2 MiB。
HTML 只通过加密通道送到浏览器并生成短时本机 Blob URL；转发服务不再缓存 HTML，也不再提供预览
能力地址。浏览器会把内容放入不透明来源的沙箱框架，不能访问父页面、存储、表单、弹窗、
顶层导航或网络；框架内部允许内联脚本，以保留交互效果。下载原文件仍使用需要确认的短时能力凭证。

设备管理只能在转发服务主机上操作。可以创建浏览器配对，也可以使用默认命令批准连接器或恢复 Token
请求；以下命令还可以列出或撤销已批准设备，而且不会输出设备 ID、请求 ID 或公钥：

```bash
docker compose exec bridge node build/server/device-admin.js pair https://codex.example.com
docker compose exec bridge node build/server/device-admin.js list-approved
docker compose exec bridge node build/server/device-admin.js revoke
```

正在运行的转发服务会在下一次心跳时发现撤销并关闭该设备的活动连接，通常不超过 30 秒，无需重启。

## Token 可能泄露时

1. 直接视为已泄露，不要等待滥用证据。
2. 运行上面的管理员 `revoke` 命令，撤销受影响的浏览器或连接器身份。如果设备私钥也可能泄露，即使 Token 仍安全，
   也应视该身份为已失陷。Web 客户端无法读取注册身份和配对元数据。
3. 只有 `BRIDGE_CLIENT_TOKEN` 泄露时，生成新随机值替换并重启转发服务。重启会关闭现有浏览器连接，
   连接器凭据仍然有效。
4. `BRIDGE_CONNECTOR_TOKEN` 泄露时，在转发服务端替换它，使用新 Token 重新运行连接器安装器，然后
   同时重启转发服务和连接器。
5. 检查 ECS/代理日志、浏览器扩展、剪贴板历史、Shell 历史、截图、CI 输出、密码管理器访问记录和
   异常连接器替换；同时轮换一并暴露的基础设施凭据。

## 不在防护范围内

Codex Anywhere 不是多租户身份提供方、零信任网关或通用远程 Shell。它不能防御已失陷的连接器电脑、
已失陷的 ECS root 账号、能够使用已批准浏览器身份的恶意扩展、所有必需凭据同时泄露，或用户主动批准
的恶意 Codex 操作。
