# 2026-10-03 代码检视与历史滚动修复

本轮从长会话的历史跳变复现开始，检查 Web 历史与实时消息合并、分页请求生命周期、图片渲染、连接重试、Connector 文件传输与路径边界、Relay 认证与转发，以及扩展授权和页签生命周期。以下是已确认并修复的问题；这不是对所有运行环境的无缺陷保证。

## 发现与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 距底部 180 像素以内仍开启自动跟随 | 用户刚向上阅读，就被进度更新拉回底部 | 只有回到底部才恢复跟随；向上输入立即取消待执行的底部定位 |
| 分页开始时记录总高度，任意中间渲染都能消费补偿 | 旧消息插入、底部增长和图片加载混在一起，补偿过早或过量 | 按可见消息及其相对位置锚定，在 React 提交和 ResizeObserver 回调中同步修正 |
| 实时尾部与分页使用不同的消息标识 | 相同图片和消息重新挂载，阅读位置和展开状态不稳定 | 按持久化消息内容、时间及上下文复用 DOM 标识；保留压缩标记原有匹配逻辑 |
| 旧分页请求结束后无条件释放加载锁 | 切换会话时可能释放新会话的分页锁 | 加载锁绑定会话选择版本；旧响应不能释放新请求的锁 |
| 旧分页与实时尾部重叠 | 相同持久化消息可能重复插入 | 分页合并排除已展示的相同消息，保留不同时间的重复发言 |
| 通用文件上传不在重连请求去重集合内 | 已接收分块或已完成上传被再次执行，产生偏移错误或找不到上传 | 对 begin、chunk、complete、cancel 按设备身份与请求 ID 去重；指纹改用 SHA-256，避免缓存整段附件请求文本 |
| 用 Windows 的 isAbsolute 判断 POSIX 路径类型 | Linux 允许范围比较意外忽略大小写，并误解反斜杠 | 依据盘符或 UNC 前缀区分路径类型，拒绝混合类型；POSIX 保持大小写敏感 |

## 重构边界

- 将 DOM 锚点和自动跟随状态提取到 `conversation-scroll.ts`，React 生命周期绑定集中在 `use-conversation-scroll.ts`；删除 App 中分散的高度补偿和额外动画帧定位。
- 保留现有会话、加密协议和文件传输接口，避免将滚动修复扩展为协议迁移。
- 没有整文件重写 App。它仍承担较多连接和会话状态职责；以后拆分应以独立的生命周期测试为前提。
