# 代码审视 — 2026-10-16

[English](code-review-2026-10-16.md) | 简体中文

本轮检查 Web 历史/请求/图片生命周期、Connector 文件处理与请求重放、Relay 认证及加密转发、扩展连接与页面授权、依赖审计和发布文档。这里只记录可复核的证据，不代表所有部署环境或网站都无缺陷。

## 已确认问题

| 问题 | 证据与修复 |
| --- | --- |
| 未完成请求可能离开重放缓存 | 挂起一个 `turn.start`，完成另外 70 次变更请求，再重连并重放同一 ID：旧处理器执行两次。`RequestReplayCache` 将未完成请求与结果 LRU 分离，限制等待数量，TTL 从结束时起算；回归只执行一次。 |
| 并发打开绕过单客户端下载限制 | 旧实现同时打开八次会创建八个下载能力。现于第一次 await 前预留名额，仅允许一个，其他客户端独立。 |
| 关闭服务后仍可能发布下载 | 在 `closeAll` 前立即发起打开，旧实现会在关闭后成功。现拒绝未完成/新增打开并关闭相关句柄。 |
| 过期清理关闭活动读取 | 测试推进时钟时，另一个客户端的忙碌下载被删除。现跳过活动读取。 |
| 最后一块期间文件变化仍返回成功 | 在最后一次 read 中改写文件，旧实现仍完成下载。现读取后重新检查快照，变化时撤销下载并报错。 |
| 部分预览先检查大小，再无界读取 | 图片和可视化读取可能跟随文件增长超过已检查大小。`bounded-file.ts` 仅分配检查过的大小，处理短读取并复核元数据，覆盖增长、截短和等长改写。 |
| 图片缓存未识别文件替换 | 替换为同大小且保留 mtime 的图片可能返回旧像素。缓存新增设备/inode/ctime，使用真实 PNG 替换验证预览更新。 |
| 版本信息和指南落后于 tag | 已有 v0.4.0，但当前指南和 package 仍标 0.3.0。现统一 0.4.1，补回 changelog 的 v0.4.0 分界，加入 `check:docs` 防止版本和链接再次漂移。 |

## 重构判断

提取两个聚焦模块：`bounded-file.ts` 管字节上限、文件快照及严格文本解码；`request-replay.ts` 管未完成/已完成变更状态。调用方仍负责路径、身份和权限校验，无需迁移线协议或已有身份。

保留 App 编排、Codex 历史投影、Relay 转发与扩展授权结构。这些模块仍较大，但缺少明确职责边界时继续拆分只会扩大改动；现有生命周期、安全和扩展回归纳入发布检查。本轮没有新增生产依赖。

## 验证与保留边界

- 四个类型检查及 451 项主测试通过，下载和加密重放场景均有修复前失败、修复后通过的记录；发布检查另包含编译后的扩展测试、生产构建和文档校验。
- npm 官方 registry 审计有两项低风险依赖条目（KaTeX 及上层 Mermaid），无中、高、严重级别条目。Mermaid 12 仍需独立完成浏览器兼容迁移。
- 单文件预览有上限，不等于大量并发请求有统一进程内存预算；下载仍在浏览器中组装 Blob。未完成请求保护仅存在于进程内，已完成结果仍有明确的 LRU/TTL 边界。
- 元数据检查识别正常并发修改，不提供事务快照。可信本地用户仍可改文件，宿主操作系统仍属于信任边界。
- 旧的日期报告保留原测试数量与验收范围；浏览器检查不证明手机真机性能，也不覆盖每一个第三方页面。
